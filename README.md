# Multimodal Document Intelligence System

An agentic RAG system that reads PDFs the way a person does: it understands prose, tables, and figures as different kinds of content, routes each question to the right modality, and answers with the source page cited. It can also read a whole document aloud, section by section, in 14 languages.

Built around the Transformer paper (*Attention Is All You Need*, arXiv:1706.03762) as the demo document, but it works with any PDF.

## Features

- **Multimodal ingestion** — each PDF page is rendered and split into text, tables, and figures. Tables are extracted as structured JSON; figures get detailed descriptions plus a saved image crop.
- **Modality-aware retrieval** — every question is classified as text, table, or chart, and retrieved from the matching vector collection, with a fallback across all collections when confidence is low.
- **Grounded answers** — answers come only from the retrieved context, with the source page and modality shown. Chart questions are answered with the actual figure image passed to the model.
- **Three ways to use a document** — ask a question, read it section by section with explanations, or paste any passage and ask about it.
- **14 languages** — answers, summaries, and explanations in English, Hindi, Telugu, Tamil, Spanish, French, German, Arabic, Japanese, Chinese, Portuguese, Korean, Italian, or Russian.
- **Three explanation styles** — simple, technical, or ELI5.
- **Voice output** — answers, summaries, and document sections read aloud in the selected language (browser speech synthesis).
- **Faithfulness evaluation** — an 8-question ground-truth set on the Transformer paper that checks whether the answer's claimed source modality matches the correct one.

## How it works

```
PDF ──► render pages (200 DPI) ──► detect tables + figures ──► Claude Haiku vision
        extracts text / table JSON / chart descriptions
              │
              ▼
        all-MiniLM-L6-v2 embeddings ──► ChromaDB (text_chunks, table_chunks, chart_chunks)
              │
              ▼
Question ──► Claude Haiku classifies modality ──► retrieve top chunk (fallback if distance > 1.2)
              │
              ▼
        Claude Sonnet 4.6 answers from context only (chart image included when relevant)
```

### Ingestion (`ingestion.py`)

1. Pages are rendered to images with `pdf2image` / Poppler at 200 DPI.
2. Tables are detected with `pdfplumber` using three strategies (lines, text, explicit), with filters that reject reversed-text and tiny-box false positives.
3. Figures are detected two ways: caption-based (Figure/Fig./Chart/Graph/Exhibit/Diagram/Plot/Image/Appendix labels) and, when no captions are found, embedded raster images above a size threshold.
4. Each region is cropped and sent to Claude Haiku 4.5 with a modality-specific prompt: prose extraction for text, structured JSON for tables, detailed description for charts.
5. Chunks are embedded with `all-MiniLM-L6-v2` and stored in three ChromaDB collections, with page number, document name, and modality as metadata. Table JSON is stored alongside the description; chart crops are saved under `stored_charts/`. Already-processed pages are skipped on re-ingestion.

### Retrieval (`router.py`)

- The question is classified as `text`, `table`, or `chart` by Claude Haiku.
- The top-1 chunk is retrieved from the matching collection. If the distance is above 1.2 (or nothing is found), all three collections are searched and the closest match wins.
- For table hits, the structured JSON rows are appended to the chunk text before answering.

### Answering (`answer_engine.py`)

- **Intent detection:** questions route to Q&A; "read the document" / "summarize the document" triggers a page-by-page full read; "what does page N say" explains a single page.
- Answers are generated by Claude Sonnet 4.6, grounded in the retrieved chunk, in the selected language and style.
- Chart answers include the stored figure image so the model sees the visualization, not just its description.

### Interface (`app.py`)

A Streamlit app with three tabs:

| Tab | What it does |
|---|---|
| Ask a Question | Q&A with page, modality, and language shown; searchable history |
| Read Document | Section-by-section viewer with original text, explanations, summaries in any language, and voice playback |
| Selected Text | Paste any passage, ask about it, or have it read aloud |

## Project structure

```
├── app.py              # Streamlit UI (main entry point)
├── ingestion.py        # PDF → multimodal chunks → ChromaDB
├── router.py           # Question classification + retrieval with fallback
├── answer_engine.py    # Intent detection + grounded answering (Claude Sonnet 4.6)
├── evaluation.py       # 8-question faithfulness evaluation (Gemini 2.5 Flash)
├── rag_pipeline.py     # Early single-collection RAG prototype (Gemini)
├── query_pipeline.py   # Early Q&A + faithfulness-check prototype (Gemini)
├── pdf_ingestor.py     # Early whole-page ingestion prototype
├── test_react.py       # Alternate Streamlit UI with full-document reading flow
├── table.py            # Inspect stored table chunks
├── check_db.py         # Inspect the documents collection
├── reset_db.py         # Wipe ChromaDB and recreate the three collections
└── test_setup.py       # Quick pdfplumber table-detection check
```

`rag_pipeline.py`, `query_pipeline.py`, and `pdf_ingestor.py` are earlier prototypes that use a single `documents` collection; the current pipeline is `ingestion.py` → `router.py` → `answer_engine.py` → `app.py`.

## Setup

**Prerequisites**

- Python 3.10+
- [Poppler](https://poppler.freedesktop.org/) (required by `pdf2image` to render PDF pages). On Windows, set `POPPLER_PATH` in `ingestion.py` to your Poppler `bin` directory; on macOS/Linux, install via your package manager (`brew install poppler` / `sudo apt install poppler-utils`) and remove the path argument.
- An Anthropic API key (Claude). A Google AI Studio key is only needed for the evaluation script and the early prototypes.

**Install**

```bash
pip install streamlit anthropic chromadb sentence-transformers pymupdf pdfplumber pdf2image pillow google-genai
```

**API keys**

Set your Anthropic key in `app.py`, `ingestion.py`, `router.py`, and `answer_engine.py` (currently a placeholder variable in each file). For the evaluation script, set the Gemini key in `evaluation.py`. Keys should be moved to environment variables before sharing or deploying.

## Usage

**Ingest a document** — either upload a PDF in the app sidebar and click Ingest, or run the pipeline directly:

```bash
python ingestion.py   # edit PDF_PATH at the bottom of the file first
```

**Run the app**

```bash
streamlit run app.py
```

The default active document is `1706.03762v7` (the Transformer paper). Switch documents by name in the sidebar after ingesting.

**Evaluate retrieval faithfulness**

```bash
python evaluation.py
```

Runs the 8-question ground-truth set and prints a per-modality and overall faithfulness report (whether the answer's claimed source modality matches the correct one).

**Reset the database**

```bash
python reset_db.py
```

## Tech stack

- **LLMs:** Claude Sonnet 4.6 (answering, explanations), Claude Haiku 4.5 (extraction, classification, summaries), Gemini 2.5 Flash (evaluation, prototypes)
- **Embeddings:** sentence-transformers `all-MiniLM-L6-v2`
- **Vector store:** ChromaDB (persistent, three collections by modality)
- **PDF processing:** PyMuPDF, pdfplumber, pdf2image + Poppler
- **UI:** Streamlit, browser Web Speech API for voice

## Notes and limitations

- Ingestion calls a vision model once per region plus once per page, so large PDFs take a while and use API credits.
- `POPPLER_PATH` in `ingestion.py` is currently a Windows path; adjust it for your system.
- The early prototype files (`rag_pipeline.py`, `query_pipeline.py`, `pdf_ingestor.py`) use a different single-collection schema and are kept for reference, not used by the app.
- Chart answers depend on the stored figure crop; if the image file is missing, the answer falls back to the chart description text.
